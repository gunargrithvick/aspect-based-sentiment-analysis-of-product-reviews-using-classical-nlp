# Project Report Structure

Use the following structure for the technical project report:

1. **Introduction** - The problem and why aspect-level sentiment is useful.
2. **System requirements** - Inputs, outputs, boundaries, and constraints.
3. **Dataset** - Dataset source, format, labels, and data validation.
4. **System design** - Processing flow and module responsibilities.
5. **Preprocessing** - Tokenization, normalization, lemmatization, POS features, and negation handling.
6. **Model implementation** - Baseline lexicon/Logistic Regression system and improved CRF/SVM system.
7. **Testing and evaluation** - Metrics, validation split, comparison, and error analysis.
8. **Results** - Tables, representative predictions, and limitations.
9. **Responsible use** - Appropriate and inappropriate uses of the system.
10. **Conclusion and future improvements** - Summary and practical next steps.
11. **Reproducibility appendix** - Commands, dependencies, dataset path, model settings, and test result.

The report should describe an implemented system and its engineering decisions. It does not need to claim a new research method.
